# Pallada.Mail — официальный канал обновлений

Этот **публичный** репозиторий предназначен для распространения установщиков Windows через [GitHub Releases](../../releases). **Не загружайте сюда письма, пароли почты, API-ключи, настройки или резервные копии.**

## Подключение в установленной Pallada.Mail v17

1. Откройте **Почтовые ящики → Обновления через интернет**.
2. Укажите: `batyabiznessman-glitch/pallada-mail-updates`.
3. Включите проверку обновлений и сохраните настройки.
4. При следующем запуске программа проверит новый *опубликованный стабильный* Release. Скачивание и установка происходят **только после подтверждения пользователя**.

Пока Releases пуст, новых версий приложение не найдёт.

## Как опубликовать выпуск

1. Соберите и **проверьте на Windows** установщик новой версии. Номер версии внутри установщика должен совпадать с тегом выпуска.
2. Откройте [Releases](../../releases), нажмите **Draft a new release**.
3. Укажите тег формата `v18.0.0` (или иной номер **выше уже установленного**), название и описание изменений.
4. Прикрепите установщик под **точным именем** `Pallada.Mail-Setup.exe` (не ZIP).
5. Опубликуйте обычный Release — не Draft и не Pre-release.
6. Проверьте, что [GitHub API](https://api.github.com/repos/batyabiznessman-glitch/pallada-mail-updates/releases/latest) показывает опубликованную версию и в `assets` есть `Pallada.Mail-Setup.exe`, размер и `sha256:` в поле `digest`.
7. Проверьте обновление на тестовой Windows-машине; сохраняйте предыдущую версию для отката.

### Исходная версия v17.0.0

Если публикуете базовую v17: переименуйте файл `Pallada.Mail-v17-Setup.exe` в `Pallada.Mail-Setup.exe` перед загрузкой на GitHub.

- Размер: `21219840` байт
- SHA-256: `6de8f632b1feb1c66bbd1a2c4c797f1558a4e84dc1521ec1a9d692ec5e808e84`

Выпуск `v17.0.0` не вызовет обновление уже установленной `v17.0.0`. Для проверки автоматического перехода потребуется отдельная, более новая и протестированная версия.

## Безопасность

- Никогда не добавляйте сюда файлы переписки (`.eml`, `.mbox`), базы данных, профили браузера и секреты.
- SHA-256 позволяет проверить целостность, но **не удостоверяет издателя**. Для защищённого канала обновлений нужна подпись установщика и проверка этой подписи перед запуском.
- Не публикуйте непроверенные на Windows сборки.
